I have completed the drafting task for SR-100's curve data.

### 1. Summary of Work
- **Curve Data Tables**: Placed three `CURVE DATA` tables in paper space on sheets **C-101**, **C-102**, and **C-103** at position `[26, 15]`. Each table lists only the curves visible on that specific sheet:
    - **C-101**: Curve 1
    - **C-102**: Curves 1 and 2
    - **C-103**: Curve 2
- **Curve Callouts**: Placed two design-anchored labels (`kind: 'curve_data'`) in **model space**. These labels create the curve number bubble with a leader pointing to the middle of the curve:
    - **C-1**: Anchored at `MC-1` of alignment `DESIGN:SR-100`.
    - **C-2**: Anchored at `MC-2` of alignment `DESIGN:SR-100`.

### 2. Key Tool Calls
1. `get_design_data(alignment="DESIGN:SR-100", kind="curves")` — retrieved curve geometry and stations.
2. `get_sheet_state(sheet="C-101/102/103")` — determined visible model bounding boxes for each sheet.
3. `place_curve_table(space="C-101/102/103", alignment="DESIGN:SR-100", curves=[...])` — placed the filtered tables on each sheet.
4. `place_label(space="model", alignment="DESIGN:SR-100", anchor="MC-1/2", kind="curve_data")` — placed the curve number bubbles on the plan.

### 3. Issues and Workarounds
- **Alignment Naming**: Initially attempted to use `SR-100`, but the alignment is owned by a reference. I had to use `DESIGN:SR-100` as prompted by the engine error: `"no alignment named 'SR-100' ... its references carry ['DESIGN:SR-100']"`.
- **Label Kind**: Tried using `kind: 'curve_bubble'`, which failed with an `invalid_params` error. I switched to `kind: 'curve_data'`, which produces the required bubble and leader.
- **Anchor Type**: Attempted to anchor labels using raw stations (e.g., `25+98.32`), but `curve_data` labels require a design anchor. I resolved this by using `MC-1` and `MC-2` (Mid-Curve points).
