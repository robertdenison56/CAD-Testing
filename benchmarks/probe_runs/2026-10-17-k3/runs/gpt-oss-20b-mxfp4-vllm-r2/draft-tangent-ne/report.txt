**1. What was created and drawn**

| Item | Details |
|------|---------|
| **Layer** | `align_MAIN` – color black, continuous linetype, 0.35 mm lineweight, description “Roadway centerline.” |
| **Alignment** | `MAIN-ST` – starts at station 10+00, geometry defined by 2 profile points (PIs). |
| **PIs (in model units)** | • PI‑1: E 2000.00 ft, N 5000.00 ft → `[2000, 5000]`  <br>• PI‑2: E 3200.00 ft, N 5000.00 ft → `[3200, 5000]` |
| **Drawn entity** | A straight line on layer `align_MAIN` connecting the two PIs (i.e., the centerline of the alignment). |

**2. Tool calls that mattered (in order)**  

```json
{
  "create_layer": {
    "name": "align_MAIN",
    "color": "black",
    "linetype": "continuous",
    "lineweight_mm": 0.35,
    "description": "Roadway centerline"
  }
}
```

```json
{
  "create_alignment": {
    "name": "MAIN-ST",
    "begin_station": "10+00",
    "pis": [
      [2000, 5000],
      [3200, 5000]
    ]
  }
}
```

```json
{
  "draw_alignment": {
    "alignment": "MAIN-ST",
    "layer": "align_MAIN"
  }
}
```

**3. Issues, work‑arounds, and arithmetic**

- **Coordinate system orientation** – The specification is in *N x, E y* form, but RoadDraft expects `[easting, northing]`. Thus I inverted the pair: N 5000 → `y=5000`, E 2000 → `x=2000`.
- **Alignment definition** – The `create_alignment` command accepts either a fully‑defined list of PI locations (`pis`) or a list of element objects (`elements`). I used the simpler `pis` form because the alignment is a single straight segment; no curves or interior points were needed.
- **End coordinate calculation** – Running due east for 1 200 ft adds that distance to the easting only:
  - `x_end = 2000 + 1200 = 3200`
  - `y_end = 5000` (unchanged)
- **Layer assignment** – I supplied the layer name in both `create_layer` and `draw_alignment`; no need to set a global current layer.
- **No errors were reported** by the engine; all validations passed automatically.

Task complete.
