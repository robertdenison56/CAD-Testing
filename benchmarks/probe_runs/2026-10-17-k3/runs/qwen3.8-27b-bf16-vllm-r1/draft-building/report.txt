## 3. Failures, confusions, workarounds

- **`traverse`/`draw_traverse` rejected a point for `start`** despite the schema describing it as "a point [x, y] … or an entity id":
  > `"message": "entity '[1500, 1200]' not found"` (same for `[1500.0, 1200.0]`)
  The engine treated the array as an entity id. **Workaround:** created a COGO point at the corner and started the traverse from the entity id `CP-001` (`start_at: "end"`), which the doc explicitly supports ("or at the end of an entity").
- **First successful traverse was a triangle, not the rectangle:** with only the two given legs, `close=true` added a straight closing course (reported as "S 63°41'24\" W 72.11' (closing); misses its start by 72.111' … precision 1:1"). I deleted `PL-001` and redrew with all four legs (three 90° right deflections), which closed exactly.
- **Coordinates I had to compute myself** (for the probe line and as a check on the engine's output; model = [easting, northing]):
  - B = A + 60 @ N 30° E: E = 1500 + 60·sin 30° = 1500 + 30 = **1530.00**; N = 1200 + 60·cos 30° = 1200 + 30√3 = 1200 + 51.961524 = **1251.961524**
  - C = B + 40 @ S 60° E (azimuth 120°): E = 1530 + 40·sin 60° = 1530 + 20√3 = 1530 + 34.641016 = **1564.641016**; N = 1251.961524 − 40·cos 60° = 1251.961524 − 20 = **1231.961524**
  - D = C + 60 @ S 30° W (azimuth 210°): E = 1564.641016 − 30 = **1534.641016**; N = 1231.961524 − 60·cos 30° = 1231.961524 − 51.961524 = **1180.00**
  - (sin 30° = 0.5, cos 30° = √3/2 ≈ 0.8660254; sin 60° = √3/2, cos 60° = 0.5.) These match the engine's computed vertices to all digits, and the final leg D→A is 40 ft @ N 60° W, confirming closure.
