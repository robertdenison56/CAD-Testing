### 2. Tool calls that mattered, in order

1. `get_document_state` + `list_sheets` + `list_references` + `get_model_state{include_references:true}` — found the design in basefile `DESIGN` and its 14 `rd_RIGHT-OF-WAY` entities; split them into left/right ROW chains.
2. `get_sheet_state{sheet:'C-102'}` — viewport VP-002 (center paper (17, 11.7), 31×18.5", model center (3325, 1250), 50 f/i).
3. `find_entities{layer:'rd_RIGHT-OF-WAY', visible_on:'C-102'}` — 10 ROW pieces visible; identified the 7 right-side ones.
4. `list_alignments{include_references:true}` — referenced alignment `DESIGN:SR-100`.
5. `get_entity` on DESIGN:LN-019/020/021/022/023/025 and AR-013/014 — full bearings, lengths, R, Δ for each piece.
6. `create_layer{name:'RD_ROW-ANNO'}`.
7. `label_segments{ids:[LN-019, AR-013, LN-020…LN-025], style:'tags', space:'C-102', table:{position:[3.0,5.5]}, layer:'RD_ROW-ANNO'}` — first pass, auto-numbered by draw order (wrong).
8. `delete_entities{ids:[TX-001…TX-007, TB-001, TB-002]}` — removed the wrong pass.
9. `label_segments{…same…, order_along:'DESIGN:SR-100'}` — re-lettered in station order → tags C1, L1, L2, L3, L4, L5, C2 + LINE TABLE TB-003 + CURVE TABLE TB-004.
10. `find_entities{space:'C-102', type:'text'}` + `get_entity{TB-003, TB-004}` + `render_sheet{sheet:'C-102'}` — verified tag contents/positions and table rows.

### 3. Failures, confusion, workarounds

- **Numbering order**: the first `label_segments` call numbered by entity draw order (L1–L5, C1, C2 with L1 on LN-020… wait, actually it labeled the first five visible *lines* L1–L5 and the two curves C1/C2, so the L-numbers happened to coincide but only by luck and the tool's message claimed 5 lines + 2 curves generically). I deleted it and re-ran with `order_along:'DESIGN:SR-100'` so numbering strictly follows stationing order as required.
- **Warning (both label_segments calls)**: `"no viewport of C-102 shows DESIGN:LN-019, DESIGN:LN-025; those segments were not labelled"` — expected and intended; those off-sheet ROW lines belong to adjacent sheets C-101/C-103.
- **Minor**: the CURVE TABLE's auto-added columns (TANGENT, CHORD BRG, CHORD) exceed the minimal columns requested, but they are standard ROW-map content and don't hurt; the required tag/RADIUS/DELTA/LENGTH are all present.
- Render images were returned as text-only in this run, so final verification was done from `get_sheet_state`/`get_entity` data (tag positions checked against model→sheet geometry: each tag sits ~3–5 ft beside its own segment, not on a neighbor).
