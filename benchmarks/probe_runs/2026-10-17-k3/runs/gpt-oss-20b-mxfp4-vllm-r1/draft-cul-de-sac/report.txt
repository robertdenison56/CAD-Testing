**Tool Calls (in order)**

1. **create_alignment**  
   ```json
   {
     "name": "OAK-CT",
     "begin_station": "10+00",
     "pis": [
       [3000, 2000],
       [3000, 2400]
     ]
   }
   ```

2. **draw_alignment**  
   ```json
   {
     "alignment": "OAK-CT",
     "layer": "align_MAIN"
   }
   ```

3. **draw_circle**  
   ```json
   {
     "space": "model",
     "center": [3000, 2400],
     "radius": 45,
     "layer": "rd_EP"
   }
   ```

4. **draw_line – West Pavement Edge**  
   ```json
   {
     "space": "model",
     "start": [2986, 2000],
     "end": [2986, 2357.22],
     "layer": "rd_EP"
   }
   ```

5. **draw_line – East Pavement Edge**  
   ```json
   {
     "space": "model",
     "start": [3014, 2000],
     "end": [3014, 2357.22],
     "layer": "rd_EP"
   }
   ```

---

**Issues / Work‑arounds**

* No errors were returned from the engine.  
* Calculations for the intersection point of the pavement edges with the bulb:  

  ```text
  r = 45 ft
  offset = 14 ft
  Δy = sqrt(r² – offset²) = sqrt(2025 – 196) = sqrt(1829) = 42.78 ft
  y‑coordinate where edges meet bulb = 2400 – 42.78 = 2357.22 ft
  ```

  Hence the end of each offset line was set to y = 2357.22 ft.  
* The alignment was defined directly by its two PI points; the API accepted this simple straight‑line definition without needing an explicit `start` key.  
* No trimming operation was required because the offset lines were manually constructed to terminate exactly at the bulb boundary.  

All required geometry has been created and drawn as specified.
