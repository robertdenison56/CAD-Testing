2. Tool calls that mattered, in order

- get_document_state {} -- 3 sheets (C-101..C-103, ANSI D), no model entities, no owned alignments, layers include V-ANNO-TEXT.
- list_alignments {include_references: true} -- one referenced alignment DESIGN:SR-100, 3 tangents, 2 curves, read-only.
- get_design_data {alignment: "DESIGN:SR-100", kind: "tangents"} -- T-1 N 90°00'00" E 1405.2668', T-2 N 71°33'54" E 1240.3557' (direction 18.4349°), T-3 N 90°00'00" E 1353.9501', with mid-stations.
- get_sheet_state for C-101, C-102, C-103 -- each has one viewport at 1"=50', 0° twist; visible model x-ranges 1000-2550, 2550-4100, 4100-5650, so T-1/T-2/T-3 fall on C-101/C-102/C-103 respectively.
- find_entities {visible_on: "C-101"} (and C-102, C-103) -- confirmed linework on every sheet is centerline + EOP at offsets ±12 + shoulder at ±20, nothing else.
- resolve_anchor {space: "C-101", alignment: "DESIGN:SR-100", anchor: "T-1", kind: "bearing"} -- dry run; auto content is bearing only (no length) and it reports place_label cannot anchor to a referenced alignment, so I used place_text with explicit content.
- station_to_xy {alignment: "DESIGN:SR-100", station: <mid-station>, offset: -6, sheet: <sheet>} x3 -- gave the paper point and direction for each text position.
- place_text x3 (stdin form) with the space/position/content/rotation listed above -- created TX-001, TX-002, TX-003, no warnings.
- get_entity {id: TX-00n} x3 -- verified stored content has plain apostrophes/quotes (no backslashes) and the bboxes sit between centerline and EOP.
- render_sheet x3 -- visual check.

3. Failures, confusions, workarounds

- No command errored. The only limitation: place_label cannot be used because the alignment is referenced. resolve_anchor said: "place_label cannot anchor to a referenced alignment; call it out with place_callout (target_anchor takes this anchor and alignment, from a sheet too), or copy the design into this document first". A callout would add a leader the task does not want, so I used place_text on the sheet with the paper point from station_to_xy (sheet param), which is the engine-sanctioned way to get a viewport position without hand arithmetic.
- The engine's auto bearing label (kind=bearing) is bearing only, no length, so the content had to be written explicitly in the requested "bearing length'" form.
- place_text's success message rendered the content as 'N 90°00\'00" E 1405.27\'' (backslash-escaped apostrophes); get_entity confirmed that was only the message's string repr and the stored content is exactly N 90°00'00" E 1405.27'.
- Judgment call: "just above the centerline" and "clear of all linework" were satisfied together by sitting the text in the 0.24" lane between the centerline and the upper EOP (0.07" clearance each side) rather than above the shoulder line 0.40" away.
