# T2: runbook

Stage *T2* of `RoadDraft_Training_Plan.md` §4: "sample the T1 checkpoint on fresh training seeds weighted to
the types it still fails, keep the 100s, retrain from base; one round, a second if the first pays".

**No checkpoint exists yet, so no step below has run against a model.** What is built and tested is the
free, local part: the round's task set, the disjointness check, and the keep rule. Everything that needs a
served checkpoint waits on T1 and on Robert's go (standing rule: "set up" means configure only).

| file | what |
|---|---|
| `src/roaddraft/eval/t2.py` | reads a checkpoint's run, weights the task types, builds the round's manifest (`python -m roaddraft.eval t2 plan`, `t2 check`) |
| `src/roaddraft/eval/taskset.py`, the *stage T2* block at the end | `T2_SEEDS`, a round's seeds, `t2_overlap` (the disjointness check) |
| `src/roaddraft/trajectories/conversations.py`, `rollouts` | a model run on a round's manifest into training conversations: kept when submitted and re-scored 100 |
| `tests/test_eval_t2.py` | all of it, with synthetic run folders and the harness's oracle, null and scripted agents |

## One round, in order

Every command from the pin's worktree, `PYTHONPATH="$PWD/src" .venv/bin/python` written `PY` below.
`CKPT` is the served checkpoint's model key, `--base-url` and the sampling flags whatever T1's eval
package settles on (the T1 smoke's are in `T1_SMOKE.md`, step 8); they are not chosen here.

**1. Run the checkpoint where its misses can be read.** A run on `d1-dev` (the checkpoint-selection run
already made for T1 serves), on any of the eight D1 training sets, or on an earlier round's manifest.

```bash
PY -m roaddraft.eval run --taskset d1-dev --model CKPT --provider openai --base-url URL --level vague --mode single --samples 1 --concurrency 1 --out results/e3-lms --run-id CKPT-d1-dev-vague
```

`d1-dev` holds only the 16 seeded types on plain sheets, three or four tasks a type. To read the hard,
twisted, crowded, revised and open-break tasks as well, add a slice of each training set (`--taskset
d1-train-hard --limit 30`, and so on); the planner takes several run folders at once. A run on a held-out
set (`d1-test`, `d1-real`, the hard sets, the pilots) is refused: what the checkpoint does on a test set
does not shape its training data.

**2. Plan the round.** Prints the type table and writes `benchmarks/tasksets/d1-train-t2-r1.json`.

```bash
PY -m roaddraft.eval t2 plan results/e3-lms/CKPT-d1-dev-vague [MORE_RUN_DIRS] --round 1 --size 600 --name d1-train-t2-r1 --dry-run
PY -m roaddraft.eval t2 plan results/e3-lms/CKPT-d1-dev-vague [MORE_RUN_DIRS] --round 1 --size 600 --name d1-train-t2-r1
PY -m roaddraft.eval t2 check d1-train-t2-r1
```

The table, one row a *cell* (a training flavour and a task type, 42 of them: `plain` is `d1-train`'s kind
of task, then `hard`, `twist`, `crowd`, `revise`, `twist-widths`, `revise-base`, `breaks`):

- `run n`, `miss`: the run's finished episodes of the cell and how many scored under 100. Episodes that
  ended in an error or have no end record are left out and counted on the line above the table.
- `miss rate`, `from`: `run` when the run met the cell: its misses over its episodes, shrunk toward a prior
  worth two episodes (the same type in the run's other flavours, else the run's overall rate). `type` or
  `overall` when the run never met the cell: the prior alone.
- `train`: the cell's share of the eight training manifests.
- `weight` = `floor x train + (1 - floor) x train x miss rate / sum(train x miss rate)`, floor 0.25
  (`--floor`). A run that passes everything, or fails everything, gives the training sets' own mix.
- `count`: whole tasks; one for every cell when the round holds 42 or more, the rest by weight.
- `kept (est.)`: `count x (1 - miss rate)`.

The manifest is refused, and nothing written, when it shares a task id or a seed with any held-out set, any
training set or another round, or holds anything that is not a seeded task on its round's seeds; and when a
manifest of that name is already there with other content (`--force` replaces it; do not, once rollouts
have run on it). Round 1 draws seeds 21000-21999, round 2 22000-22999; no other set uses 21000-22999.
Commit the manifest with the round: the rollouts are held to it.

**3. Sample the checkpoint on the round's manifest.**

```bash
PY -m roaddraft.eval run --taskset d1-train-t2-r1 --model CKPT --provider openai --base-url URL --level vague --mode single --samples 1 --concurrency 1 --out results/e3-lms --run-id CKPT-t2-r1-vague
```

The same harness, prompt, tools and budgets as any D1 run. `--samples K` draws K rollouts a task; the
converter writes the first kept one of each. The references are about a quarter explicit (plan §3,
*Format*); whether a round also samples `--level explicit` is not decided here.

**4. Keep the 100s.**

```bash
PY -m roaddraft.trajectories.conversations rollouts results/e3-lms/CKPT-t2-r1-vague --taskset d1-train-t2-r1 --jobs 6
```

Writes `results/training/d1-train-t2-r1-<level>.jsonl` beside the references, and the set's tally into
`summary.json` (`variant: rollouts`, kept, and every drop by reason). A rollout is kept when, in this order:

1. it ended on `submit` (`not_submitted` otherwise: a budget trip, an error, no end record), in a text
   mode (`vision`), with no turn the harness had to nudge (`nudged`);
2. its task is in the round's manifest and rebuilds to the episode's prompt hash, truth and starting
   document, and the tools for its scope have its tool digest (`no_task`, `prompt`, `truth`, `start`,
   `tools`): so run step 4 on the pin step 3 ran on;
3. its journal, replayed and re-scored by the current verifier, has an effective score of 100 (`score`);
4. the finished document passes the two checks the verifier does not make: on a twisted sheet the
   lettering was made for the twist (`twist_ignored`), on a revised sheet nothing was left stale
   (`left_stale`). `--audit none` leaves these two out.

The grounded audit of the turns (every value traced to the task text, a result or a stated rule) is **not**
run on rollouts. It reads the scripted drafter's shown work; the plain oracle fails it too (tested).

The command refuses any task set that is not a T2 round's: a run on a held-out set is never training data,
and a rollout on a reference set's task would be written under its reference's conversation id.

**5. Rebuild the dataset and retrain from base.**

```bash
PYTHON_WITH_TOKENIZERS -I scripts/training_tokens.py results/training
PY -m roaddraft.trajectories.conversations card
PYTHON_WITH_TRAINER scripts/training_lora.py --data results/training --out OUT --prepare-only
```

The token count and the card take the new files as they take any `*.jsonl` there; the card gains a line
saying which sets are rollouts. The trainer reads every file that is not `*-faults.jsonl` as plain
conversations, so the T2 files train with the references unless `--sets` leaves them out. The retrain itself
is T1's command with the larger folder, from the base model, not from the T1 adapter (plan §4).

**6. A second round**, if the first pays: plan it from the checkpoint the first round trained, with
`--round 2`. The run of step 3 can be one of its run folders: each T2 task carries its flavour, so every
cell is then read from the run itself.

## Measured, estimated, waiting

**Measured on the Mac, 2026-11-15, with no model** (`tests/test_eval_t2.py`, 29 tests, and by hand):

- A 600-task round planned from a 50-episode `d1-dev` run builds in 46 s and leaves 3 of its seeds out
  (the builder fell to another type on them); a 900-task round leaves 9 of 1,000. Both pass `t2 check`.
- On a 48-task round (every cell at least once): the oracle scores 100 on all 48 through `eval run`, the
  null agent 0 on every task but the revised sheets (handed over finished, they score something
  untouched, as `d1-train-revise`'s do) and under 100 on all; the converter keeps the oracle's 48 and
  drops the null agent's 48 as `score`.
- Lettering made without the twist is kept by the bare rule on some twisted tasks (it scores 100) and
  dropped as `twist_ignored` by the default. This is the grounded recorder's own finding
  (`grounded.twist_ignored`), reproduced on T2 tasks.
- `eval taskset` reports every existing manifest current; no existing task id, prompt, tool definition or
  manifest changed.

**Estimated:**

- Every `miss rate` whose `from` is not `run`, and every `kept (est.)`.
- A `miss rate` from a `d1-dev` run rests on three or four episodes a type at k = 1. The shrinkage keeps
  one episode from deciding a cell; it does not make three episodes a measurement.
- The cost of a round (plan §4: "$50-140 a round (estimate)") is the plan's figure and is not derived
  here. What this tooling fixes is the count: episodes = tasks x levels x samples.

**Waiting on a checkpoint:**

- The checkpoint's miss rates, and so the real table.
- The yield: how many of a round's rollouts are kept, and how many are lost to each reason. `nudged` and
  `twist_ignored` cannot be guessed from the references.
- Whether weighting toward the failed types pays. A cell the checkpoint always fails yields nothing
  (`kept (est.)` near 0), which the plan's design row says of the base model's hard tasks. The floor
  keeps the easy cells in; if the kept set comes out as only easy types, lower the weighting
  (`--floor` toward 1) or raise `--samples` on the hard cells.
- Samples a task, the sampling temperature, and whether rollouts are drawn at the explicit level.
- Thinking: a trained checkpoint is served with thinking off (`T1_SMOKE.md`, section 1). The harness does
  not send a model's thinking back, so it is not in a rollout's conversation either way.
- Token lengths of the kept rollouts against the 131,072 limit, and the retrain's cost and delta.
